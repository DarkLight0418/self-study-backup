## 1쪽. DevOps · 테스트 · CI/CD · 모니터링 · 설정

### DevOps 전체 흐름
- DevOps = 빠르고 안정적이며 반복 가능한 전달을 위한 **문화 + 프로세스 + 도구**.
- 전통 방식 문제 = `내 PC에서는 됨` / 운영 환경 불일치 / 수동 배포 / 긴 릴리스 / 장애 사후 대응.
- 목표 = 작은 변경 자주 배포, 자동화, 안정성, 가시성, 협업, 공동 책임.
- `[손필기]` 흐름: `기획·요구사항 → 설계 → 코드 구현 → 테스트 → 배포 → 피드백`.
- `[손필기]` DevOps = 회복력·가용성·협업·긴밀한 운영 문화와 연결.

### CALMS
- **C** Culture/Collaboration: 같은 목표, 공동 책임, 실패는 시스템 개선 기회.
- **A** Automation: CI/CD, IaC, 테스트 자동화.
- **L** Lean: 작은 단위 변경, 불필요한 승인·수동 작업 제거.
- **M** Measurement: 배포 빈도, 실패율, MTTR, 로그·메트릭·트레이싱.
- **S** Sharing: 로그, 지표, 노하우, 포스트모템 공유.
- `[손필기]` 측정 = 정량 데이터로 문제 보기, 공유 = 개발·운영팀이 같은 정보를 봄.

### CI/CD
```text
Git push → 빌드 → 테스트 → 이미지 빌드/푸시 → 배포 → 출시 → 모니터링 → 피드백
```
- CI = 자동 빌드·테스트, 오류 조기 발견.
- CD Delivery = 언제든 배포 가능한 상태 / CD Deployment = 운영까지 자동 배포.
- Deploy = 환경에 올려둠, Release = 실제 트래픽 보냄.
- 점진 출시 = 카나리, 블루/그린, A/B, 서비스 메시 라우팅.
- `[손필기]` 새 컨테이너에 바로 트래픽 보내지 말고, 검증 후 점진 전환.
- 모노리포 = 한 저장소에 모두 저장 / 멀티리포 = 서비스별 여러 저장소.

### Docker · Kubernetes · IaC
- Docker = 앱 + 실행환경을 이미지로 패키징 → 환경 차이 해결.
- Docker 흐름 = `Dockerfile → docker build → docker run`.
- K8s = 선언형 YAML, 자동 배포·확장·복구, 롤링 업데이트, 로드밸런싱, 오토스케일링.
- K8s 키워드 = Deployment, Service, Ingress, ConfigMap, Secret, Helm.
- IaC = 서버·네트워크·보안 설정을 코드로 관리 → 재현 가능, 실수 감소, 버전 관리.
- `[손필기]` Docker = 일관성, K8s = 운영 자동화, Helm = Chart 단위 관리.

### 테스트
- Test Double = Mock(상호작용), Fake(실제처럼), Stub(지정값 반환).
- 테스트 피라미드 = Unit → Service → UI.
- 주요 테스트 = 통합, 성능, 부하, 보안/침투, 스모크, 카나리, A/B, 카오스, 퍼징, Jepsen.
- 실서비스 테스트 = 배포 전 → 배포 → 출시 → 출시 후.
- `[손필기]` 카나리 = 일부 트래픽 검증, 카오스 = 장애 주입 후 회복력 확인.

### 개발 환경·도구
- 로컬 = 코드 편집·유닛 테스트 / 클라우드·클러스터 = 통합 테스트·PR·CI·배포·모니터링.
- Minikube = 단일 노드 K8s / Docker Compose = 여러 컨테이너 묶음 실행.
- Skaffold·Draft·KSync = 빌드·배포 자동화 / Telepresence = 로컬 서비스와 원격 K8s 연결.

### 모니터링·관측성
- Monitoring = 상태 확인 / Observability = 원인 추적.
- 3요소 = Log, Metric, Tracing.
- 기본 메트릭 = 트래픽, 지연, 에러, 이용률.
- Prometheus = Counter·Gauge·Histogram·Summary / Grafana = 대시보드 / Jaeger = 분산 추적.
- Tracing = CID로 요청 이동 추적, Span = 작업 단위.
- Health/Liveness = HTTP 200 건강 확인 / Readiness = 트래픽 받을 준비 확인.
- `[손필기]` 로그 = 동일 시간대·형식, debug/info/error 분류, 민감정보 제외, CID 부여.

### 설정 관리
- 원칙 = 코드와 설정 분리, 환경별 설정 분리.
- ConfigMap = 일반 설정 / Secret = 비밀번호, API Key, 인증서.
- Secret 주의 = 파드 직접 저장 금지, 환경 변수 로깅 금지, 가능하면 파일·볼륨 사용.
- Helm Chart = K8s 자원 묶음 설치·업그레이드 / CNAB = 복잡한 앱 번들링.
- `[손필기]` 설정 예 = URL, DB 암호, 계정/PW, 포트, 메트릭 포트, DB 연결 문자열.

## 2쪽. 클라우드 네이티브 모범 사례

### 클라우드 네이티브로 이동
- 단순 이전 = IaaS/Lift & Shift에 가까움. 목표 = 서비스 분리, 운영 자동화, 확장성.
- 재설계 이유 = 큰 코드베이스, 느린 출시, 계층별 다른 확장 요구, 새 기술 적용.
- 전략 = 단순 서비스 먼저 분리 → 작은 규모 운영 학습 → 데이터·코드 점진 분리.
- ACL = Facade/Adapter로 프로토콜·스키마 변환.
- Strangler = 게이트웨이가 요청을 새 서비스·함수로 점진 라우팅.
- 데이터 마이그레이션 = 공유 DB 분해, 새 DB와 기존 DB 공존 후 기존 DB 제거.
- `[손필기]` ACL은 Wrapper/Adapter 느낌, API Gateway가 모놀리스와 새 서비스 사이 완충.

### 회복력·장애 대응
- 회복력 = 장애 시 다운타임·데이터 유실을 줄이는 능력.
- Retry = 상수 / 선형 / 지수 백오프, 무한 재시도 금지.
- Circuit Breaker = 실패 누적 시 요청 차단, 연쇄 장애 방지.
- Graceful Degradation = 일부 장애에도 이해 가능한 수준의 기능 제공.
- Bulkhead = 정상 부분을 독립 그룹으로 분리해 장애 격리.
- Liveness = 재시작 판단 / Readiness = 트래픽 수신 준비 판단.
- Rate limiting = 들어오는 요청 제한 / Throttling = 나가는 요청 제한.
- `[손필기]` 일시적 장애와 영구 장애를 구분, 자원 제한은 시스템 전체 보호 목적.

### 보안 강화
- 공유 책임 모델 = 앱 공급자 + 클라우드 공급자.
- 최소 권한, 계정·구독·테넌트 분리, 격리 보장.
- Secret, 관리형 보안 저장소, 저장 시 암호화, 통신 시 TLS/HTTPS.
- Federated ID = 인증·권한 관리 위임.
- RBAC = 역할 기반 접근 제어 / Network Policy = 허용되지 않은 Pod 연결 차단.
- `[손필기]` North-South = 외부↔클러스터, East-West = 서비스↔서비스 내부 통신.

### 데이터 다루기
- 관리형 DB·분석 서비스 = 배포·관리 부담 감소.
- 데이터스토어 선택 기준 = 데이터 타입, 읽기·쓰기 패턴, 비용, 운영 난도.
- 고가용성 = 여러 리전·존 / 확장성 = 파티셔닝·복제.
- 성능 = 오버페칭·chatty I/O 회피, 필요한 데이터만 가져오기.
- DB와 비즈니스 로직 분리, 실서비스와 유사한 데이터로 테스트.
- `[손필기]` 데이터 계층은 관리 난도가 높으므로 운영 부담을 줄이는 선택이 중요.

### 성능과 확장성
- 성능 = 일정 시간 동안 작업 처리 정도 / 확장성 = 성능 저하 없이 부하 처리 능력.
- Stateless 서비스 = scale-out/in에 유리.
- HPA = CPU·메모리·커스텀 메트릭 기반 파드 스케일링.
- Cluster Autoscaler = 파드 스케일 불가 시 노드 수 증가.
- Cache = 자주 쓰는 데이터 캐싱, 속도 향상.
- Partitioning = 여러 인스턴스로 작업 분산.

### 함수·운용
- 함수 = 단일 목적, 단일 책임, 가볍고 단순하게, 상태 없게.
- 함수 직접 연쇄 호출 지양 → 큐·이벤트·데이터스토어로 연결.
- FaaS = 실행 시간 제한, 큰 함수는 작은 함수로 리팩터링.
- 운용 = 작은 배포, CI/CD 정의를 구성요소와 함께 저장, 무중단 출시, 롤백 가능.
- 불변 인프라, 컨테이너화된 빌드, IaC, Namespace 환경 격리, 브랜치-배포 버전 연결.
- `[손필기]` 함수는 “목적 하나”, 운용은 “트래픽을 언제 보낼지”가 핵심.

### 로깅·서비스 커뮤니케이션
- KPI, 기본 메트릭 = 트래픽·지연·에러.
- 태그 = 구성요소명, 함수명, 환경, 리전.
- API 계약 = 내부 세부사항 유출 금지, 업데이트 시 계약 만족 테스트.
- 하위 호환 = 기존 클라이언트가 새 서버와 동작 / 상위 호환 = 미래 데이터 형식 처리.
- 비동기 통신 선호, JSON보다 gRPC/protobuf로 메시징 부하 감소 가능.
- Queue/Stream = 트래픽 스파이크 버퍼링 / Batch = 여러 요청 한 번에 처리.
- Claim-check = 큰 메시지는 DB에 저장, 메시지에는 참조만 전달.

### 컨테이너 모범 사례
- 신뢰 가능한 저장소, 검증된 이미지, 취약점 스캔, 명시적 이미지 태그.
- Docker build cache, 작은 베이스 이미지, 필요한 파일만 포함.
- privileged 모드 금지, 필요 기능은 분리 후 인프라로 제공.
- 하나의 컨테이너에는 하나의 애플리케이션.
- 컨테이너 데이터 저장 금지 → 볼륨 사용.
- 이미지 내부 비밀정보·설정 저장 금지 → Secret/환경 변수/마운트 파일 사용.
- `[손필기]` 컨테이너는 휘발성이므로 데이터·비밀정보는 외부로 분리.

## 최종 비교 암기표

| 비교 | 핵심 |
|---|---|
| CI / CD | CI는 빌드·테스트, CD는 배포 가능/운영 배포 |
| Deploy / Release | 배포는 올려둠, 출시는 트래픽 보냄 |
| Monitoring / Observability | 상태 확인 / 원인 추적 |
| ConfigMap / Secret | 일반 설정 / 민감 정보 |
| Rate limiting / Throttling | 들어오는 요청 제한 / 나가는 요청 제한 |
| Scale-up / Scale-out | 한 대를 키움 / 여러 대로 나눔 |
| Queue / PubSub | 한 소비자 처리 / 여러 구독자 전달 |
| Liveness / Readiness | 재시작 판단 / 트래픽 수신 준비 판단 |
