# 컴퓨터구조 단답형·서술형 압축 노트

> 목적: 객관식 정답 암기가 아니라 **개념명 - 정의 - 동작 순서 - 비교 포인트 - 계산 공식**을 빠르게 꺼내기 위한 시험 대비 노트.
>
> 사용법: 각 개념을 `개념명 = 한 줄 정의`로 먼저 외우고, 서술형은 `정의 → 동작 → 필요성 → 비교/주의` 순서로 확장한다.

---

## 0. 단답형·서술형 공부 프레임

### 0-1. 단답형 답안 공식

```text
개념명 = 핵심 기능 + 위치/대상 + 목적
```

예시:

```text
제어장치 = 명령어를 해독하고 CPU 내부 동작을 제어하는 장치
캐시 = CPU와 주기억장치의 속도 차이를 완화하는 고속 임시 기억장치
DMA = CPU 개입을 줄이고 입출력 장치와 기억장치가 직접 데이터를 주고받는 방식
인터럽트 = 현재 작업을 잠시 중단하고 예외적 사건을 먼저 처리하게 하는 요청
```

### 0-2. 서술형 답안 공식

```text
1문장: 개념 정의
2문장: 왜 필요한가
3문장: 어떻게 동작하는가
4문장: 장점/주의점/비교
```

예시:

```text
인터럽트는 CPU가 프로그램을 실행하는 도중 입출력 완료, 오류, 예외 같은 사건이 발생했을 때 이를 우선 처리하도록 알리는 신호이다. CPU가 계속 장치 상태를 검사하지 않아도 되므로 효율적인 입출력 처리가 가능하다. 인터럽트가 발생하면 CPU는 현재 상태를 저장하고 인터럽트 서비스 루틴을 실행한 뒤 원래 프로그램으로 복귀한다. 단, 우선순위와 중첩 처리, 마스킹 여부를 함께 고려해야 한다.
```

### 0-3. 계산형 답안 공식

```text
주어진 단위 확인 → 주소 지정 단위 확인 → 2의 거듭제곱으로 변환 → 공식 적용
```

핵심:

```text
주소선 n개 → 2^n개의 주소 지정 가능
Byte 주소 지정이면 2^n Byte 접근 가능
주소선 수 = log2(주소 개수)
주소 개수 = 전체 기억용량 / 한 주소가 가리키는 크기
```

# 1. 제어장치(Control Unit)

## 1-1. 핵심 정의

```text
제어장치(Control Unit, CU) = 명령어를 해독하고 CPU 내부 장치에 제어 신호를 보내 명령어 실행 과정을 조정하는 장치
```

- 핵심 기능: 명령어 해독, 제어 신호 생성, 데이터 흐름 제어
- 직접 하는 일 아님: 산술 연산 자체는 ALU, 데이터 저장은 레지스터/기억장치
- 시험 키워드: `명령어 해독`, `제어 신호`, `명령어 사이클`, `PC`, `IR`, `MAR`, `MDR/MBR`

### 단답형 답안

| 용어 | 답안 |
|---|---|
| 제어장치 | 명령어를 해독하고 CPU의 동작 순서를 제어하는 장치 |
| 제어 신호 | CPU 내부 장치와 기억장치, 입출력 장치의 동작을 지시하는 신호 |
| 명령어 사이클 | 하나의 명령어를 인출하고 실행하기까지의 전체 과정 |

## 1-2. 명령어 사이클

```text
명령어 사이클 = CPU가 명령어 하나를 가져와 해독하고 실행을 완료하기까지의 전체 과정
```

기본 흐름:

```text
인출(fetch) → 해독(decode) → 오퍼랜드 인출/주소 계산 → 실행(execute) → 인터럽트 검사
```

사이클 기준:

```text
Fetch cycle → Indirect cycle(조건부) → Execute cycle → Interrupt cycle(조건부)
```

| 사이클 | 한 줄 정의 | 필수 여부 | 핵심 키워드 |
|---|---|---|---|
| Fetch cycle | 기억장치에서 명령어를 CPU로 가져오는 단계 | 모든 명령어에서 필수 | PC, MAR, IR, PC 증가 |
| Indirect cycle | 간접 주소 지정에서 실제 오퍼랜드 주소를 구하는 단계 | 간접 주소일 때만 | 유효 주소, 오퍼랜드 주소 |
| Execute cycle | 명령어가 요구하는 실제 연산/이동을 수행하는 단계 | 일반적으로 필수 | ALU, 레지스터, 메모리 접근 |
| Interrupt cycle | 인터럽트 요청이 있으면 현재 상태를 저장하고 ISR로 이동하는 단계 | 인터럽트 발생 시 | 상태 저장, ISR, 복귀 |

## 1-3. Fetch Cycle 세부 흐름

```text
PC → MAR → Memory → MDR/MBR → IR → Decode → PC 증가
```

- PC(Program Counter): 다음에 실행할 명령어의 주소 저장
- MAR(Memory Address Register): 기억장치에 접근할 주소 저장
- MDR/MBR(Memory Data/Buffer Register): 기억장치에서 읽거나 쓸 데이터 임시 저장
- IR(Instruction Register): 현재 인출된 명령어 저장

주의:

```text
Fetch cycle은 명령어를 실행하는 단계가 아니라 실행할 명령어를 가져오는 단계이다.
```

## 1-4. 하드와이어드 제어와 마이크로프로그램 제어

| 구분 | 하드와이어드 제어 | 마이크로프로그램 제어 |
|---|---|---|
| 방식 | 논리 회로로 제어 신호 생성 | 제어 기억장치의 마이크로명령어로 제어 |
| 장점 | 빠름 | 수정·확장 상대적으로 쉬움 |
| 단점 | 설계 변경 어려움 | 하드와이어드보다 느릴 수 있음 |
| 적합 | RISC, 단순 명령어 구조 | CISC, 복잡한 명령어 구조 |

### 서술형 답안 예시

```text
제어장치는 CPU가 명령어를 올바른 순서로 실행하도록 제어 신호를 발생시키는 장치이다. 명령어가 기억장치에서 인출되면 제어장치는 이를 해독하고, ALU, 레지스터, 기억장치, 입출력 장치에 필요한 제어 신호를 보낸다. 따라서 제어장치는 CPU 내부 데이터 흐름과 명령어 실행 순서를 조정하는 중심 역할을 한다. 다만 실제 산술·논리 연산은 ALU가 수행한다.
```

# 2. 기억장치(Memory)

## 2-1. 핵심 정의

```text
기억장치 = 프로그램과 데이터를 저장하는 장치
```

컴퓨터의 기억장치는 속도, 용량, 가격에 따라 계층 구조를 이룬다.

```text
레지스터 → 캐시 → 주기억장치(RAM) → 보조기억장치(SSD/HDD)
빠름/비쌈/작음                         느림/저렴/큼
```

## 2-2. 기억장치 계층 구조

| 구분 | 위치 | 속도 | 용량 | 휘발성 | 핵심 역할 |
|---|---|---:|---:|---|---|
| 레지스터 | CPU 내부 | 가장 빠름 | 매우 작음 | 보통 휘발성 | 연산에 직접 쓰는 값 저장 |
| 캐시 | CPU 내부/근처 | 매우 빠름 | 작음 | 휘발성 | 자주 쓰는 데이터 임시 저장 |
| 주기억장치 RAM | 메인보드 | 보통 | 중간 | 휘발성 | 실행 중인 프로그램/데이터 저장 |
| ROM | 메인보드 | 읽기 중심 | 작음 | 비휘발성 | 부팅 관련 펌웨어 저장 |
| 보조기억장치 | SSD/HDD | 상대적으로 느림 | 큼 | 비휘발성 | 장기 저장 |

### 단답형 답안

| 용어 | 답안 |
|---|---|
| RAM | 실행 중인 프로그램과 데이터를 저장하는 휘발성 주기억장치 |
| ROM | 전원이 꺼져도 내용이 유지되는 읽기 중심의 비휘발성 기억장치 |
| 캐시 | CPU와 주기억장치 사이의 속도 차이를 줄이는 고속 임시 기억장치 |
| 지역성 | 최근 사용한 데이터나 인접한 데이터가 다시 사용될 가능성이 높은 성질 |

## 2-3. RAM, ROM, 캐시

### RAM

- Random Access Memory
- 실행 중인 프로그램과 데이터 저장
- 전원이 꺼지면 내용 소멸
- 종류: SRAM, DRAM

| 구분 | SRAM | DRAM |
|---|---|---|
| 구조 | 플립플롭 기반 | 커패시터 기반 |
| 속도 | 빠름 | SRAM보다 느림 |
| 가격 | 비쌈 | 저렴 |
| 용도 | 캐시 | 주기억장치 |
| 특징 | refresh 불필요 | refresh 필요 |

### ROM

- 비휘발성 기억장치
- 부팅 프로그램, 펌웨어 저장에 사용
- 읽기 중심

### 캐시

```text
캐시 = 자주 접근할 가능성이 높은 데이터나 명령어를 CPU 가까이에 두어 평균 접근 시간을 줄이는 기억장치
```

- 핵심 원리: 지역성(locality)
- 시간 지역성: 최근 사용한 데이터가 다시 사용될 가능성
- 공간 지역성: 사용한 데이터 근처의 데이터가 사용될 가능성
- 캐시 적중(hit): 원하는 데이터가 캐시에 있음
- 캐시 미스(miss): 원하는 데이터가 캐시에 없어 주기억장치 접근 필요

## 2-4. 기억용량·주소선 계산 핵심

### 가장 중요한 공식

```text
주소선 n개 → 2^n개의 주소 지정 가능
주소선 수 n = log2(주소 개수)
주소 개수 = 전체 기억용량 / 한 주소가 가리키는 크기
```

### Byte 주소 지정일 때

```text
주소선 n개 → 2^n Byte 접근 가능
```

예시:

```text
주소선 20개 → 2^20 Byte = 1MB
주소선 32개 → 2^32 Byte = 4GB
```

### Word 주소 지정일 때

```text
전체 기억용량 = 주소 개수 × 워드 크기
주소 개수 = 전체 기억용량 / 워드 크기
주소선 수 = log2(주소 개수)
```

## 2-5. 계산 예시: 기억용량 - 주소선 수

### 예시 1. 1MB 기억장치가 Byte 단위로 주소 지정된다. 필요한 주소선 수는?

```text
1MB = 2^20 Byte
Byte 주소 지정 → 주소 개수 = 2^20개
주소선 수 = log2(2^20) = 20개
```

정답:

```text
20개
```

### 예시 2. 64KB 기억장치가 Byte 단위로 주소 지정된다. 필요한 주소선 수는?

```text
64KB = 64 × 1024B = 2^6 × 2^10B = 2^16B
주소 개수 = 2^16개
주소선 수 = 16개
```

정답:

```text
16개
```

### 예시 3. 주소선이 16개, 데이터선이 8개인 기억장치의 용량은?

```text
주소선 16개 → 주소 개수 = 2^16개
데이터선 8개 → 한 주소당 8bit = 1Byte
전체 용량 = 2^16 Byte = 64KB
```

정답:

```text
64KB
```

### 예시 4. 1M × 16bit 기억장치의 주소선과 데이터선은?

```text
1M개의 주소 = 2^20개 주소 → 주소선 20개
한 주소당 16bit → 데이터선 16개
전체 용량 = 1M × 16bit = 16Mbit = 2MB
```

정답:

```text
주소선 20개, 데이터선 16개
```

### 예시 5. 4GB 기억장치를 Byte 단위로 주소 지정할 때 주소선 수는?

```text
4GB = 4 × 2^30B = 2^2 × 2^30B = 2^32B
주소선 수 = 32개
```

정답:

```text
32개
```

### 계산 실수 방지

| 실수 | 올바른 판단 |
|---|---|
| 1KB를 1000B로 계산 | 컴퓨터구조 기본 문제에서는 보통 1KB = 2^10B |
| 주소선과 데이터선을 혼동 | 주소선은 주소 개수, 데이터선은 한 번에 전달되는 데이터 폭 |
| bit와 Byte 혼동 | 1Byte = 8bit |
| 전체 용량만 보고 바로 주소선 계산 | 한 주소가 몇 bit/Byte를 가리키는지 먼저 확인 |

### 서술형 답안 예시

```text
기억장치는 프로그램과 데이터를 저장하는 장치이며 CPU와 가까울수록 빠르지만 용량이 작고 비싸다. 레지스터와 캐시는 CPU 가까이에 있어 속도가 빠르고, 주기억장치는 실행 중인 프로그램과 데이터를 저장한다. 보조기억장치는 속도는 느리지만 용량이 크고 전원이 꺼져도 데이터가 유지된다. 이러한 계층 구조는 속도와 비용, 용량 사이의 균형을 맞추기 위한 설계이다.
```

# 3. 보조기억장치(Secondary Storage)

## 3-1. 핵심 정의

```text
보조기억장치 = 전원이 꺼져도 프로그램과 데이터를 장기적으로 저장하는 비휘발성 저장장치
```

- 대표 예: HDD, SSD, USB, 광디스크
- 주기억장치보다 느리지만 용량이 크고 비휘발성
- 운영체제, 응용 프로그램, 사용자 파일 저장

### 단답형 답안

| 용어 | 답안 |
|---|---|
| 보조기억장치 | 데이터를 장기 보관하는 비휘발성 저장장치 |
| HDD | 자기 디스크를 회전시켜 데이터를 읽고 쓰는 저장장치 |
| SSD | 플래시 메모리를 이용해 데이터를 저장하는 반도체 저장장치 |
| 접근 시간 | 원하는 데이터에 도달하여 읽기 시작하기까지 걸리는 시간 |

## 3-2. HDD 구조와 성능 요소

```text
플래터 → 트랙 → 섹터
```

- 플래터(platter): 데이터를 저장하는 원판
- 트랙(track): 플래터의 동심원 형태 저장 구역
- 섹터(sector): 트랙을 나눈 최소 저장 단위
- 실린더(cylinder): 여러 플래터에서 같은 반지름의 트랙 집합

HDD 접근 시간 구성:

```text
접근 시간 = 탐색 시간(seek time) + 회전 지연(rotational latency) + 전송 시간(transfer time)
```

| 요소 | 의미 |
|---|---|
| 탐색 시간 | 헤드를 원하는 트랙으로 이동하는 시간 |
| 회전 지연 | 원하는 섹터가 헤드 아래 올 때까지 기다리는 시간 |
| 전송 시간 | 실제 데이터를 읽거나 쓰는 시간 |

## 3-3. SSD 특징

```text
SSD = 플래시 메모리를 사용하는 비휘발성 반도체 저장장치
```

- 기계적 회전 부품 없음
- 임의 접근 속도 빠름
- 충격에 강함
- HDD보다 가격 대비 용량이 작을 수 있음
- 쓰기 수명 관리 필요: wear leveling

## 3-4. HDD와 SSD 비교

| 구분 | HDD | SSD |
|---|---|---|
| 저장 방식 | 자기 디스크 | 플래시 메모리 |
| 기계 부품 | 있음 | 없음 |
| 임의 접근 | 느림 | 빠름 |
| 소음/진동 | 있음 | 거의 없음 |
| 충격 내성 | 약함 | 강함 |
| 가격 대비 용량 | 큼 | HDD보다 작을 수 있음 |
| 주요 약점 | 탐색 시간, 회전 지연 | 쓰기 수명, 가격 |

## 3-5. RAID 간단 정리

| RAID | 핵심 | 장점 | 단점 |
|---|---|---|---|
| RAID 0 | 스트라이핑 | 속도 향상 | 장애 복구 불가 |
| RAID 1 | 미러링 | 안정성 향상 | 저장 효율 낮음 |
| RAID 5 | 패리티 분산 저장 | 용량과 안정성 균형 | 쓰기 부담, 복구 부담 |

### 서술형 답안 예시

```text
보조기억장치는 전원이 꺼져도 데이터를 보존하는 비휘발성 저장장치이다. 주기억장치보다 속도는 느리지만 용량이 크고 운영체제, 프로그램, 사용자 파일을 장기적으로 저장한다. HDD는 자기 디스크와 헤드를 이용하므로 탐색 시간과 회전 지연이 발생하지만 가격 대비 용량이 크다. SSD는 플래시 메모리를 사용하므로 기계적 지연이 적고 빠르지만 가격과 쓰기 수명 관리가 고려된다.
```

# 4. 버스와 입출력(Bus and I/O)

## 4-1. 버스 핵심 정의

```text
버스 = CPU, 기억장치, 입출력 장치 사이에서 데이터와 주소, 제어 신호를 전달하는 공통 통로
```

### 버스의 3요소

| 구분 | 전달 내용 | 핵심 의미 |
|---|---|---|
| 주소 버스 | 접근할 기억장치/입출력 장치 주소 | 폭이 클수록 주소 지정 가능 공간 증가 |
| 데이터 버스 | 실제 데이터 | 폭이 클수록 한 번에 전송 가능한 데이터 증가 |
| 제어 버스 | 읽기/쓰기, 인터럽트, 버스 승인 등 제어 신호 | 동작 방향과 타이밍 제어 |

### 단답형 답안

| 용어 | 답안 |
|---|---|
| 주소 버스 | CPU가 접근할 기억장치나 장치의 주소를 전달하는 버스 |
| 데이터 버스 | CPU와 기억장치, 입출력 장치 사이에서 실제 데이터를 전달하는 버스 |
| 제어 버스 | 읽기, 쓰기, 인터럽트 등 동작 제어 신호를 전달하는 버스 |
| 버스 폭 | 한 번에 전달할 수 있는 비트 수 |

## 4-2. 주소 버스와 데이터 버스 계산 감각

```text
주소 버스 n비트 → 2^n개의 주소 지정 가능
데이터 버스 m비트 → 한 번에 m비트 데이터 전송 가능
```

예시:

```text
주소 버스 20비트 → 2^20개 주소
데이터 버스 16비트 → 한 번에 16bit 전송
```

주의:

```text
주소 버스 폭은 기억공간의 개수와 관련되고, 데이터 버스 폭은 한 번에 옮기는 데이터 크기와 관련된다.
```

## 4-3. 입출력 방식

### 1) 프로그램 제어 입출력(Programmed I/O, Polling)

```text
CPU가 입출력 장치의 상태를 반복적으로 검사하면서 데이터를 주고받는 방식
```

- 장점: 구조 단순
- 단점: CPU가 계속 확인하므로 낭비 큼
- 키워드: polling, busy waiting

### 2) 인터럽트 기반 입출력(Interrupt-driven I/O)

```text
입출력 장치가 준비되거나 작업이 끝났을 때 CPU에 인터럽트를 보내는 방식
```

- 장점: CPU가 계속 기다리지 않아도 됨
- 단점: 인터럽트 처리 오버헤드 발생
- 키워드: interrupt request, ISR

### 3) DMA(Direct Memory Access)

```text
CPU가 매번 데이터를 옮기지 않고 DMA 제어기가 기억장치와 입출력 장치 사이의 데이터 전송을 직접 수행하는 방식
```

- 장점: 대용량 데이터 전송에 효율적
- 단점: 버스 사용권 조정 필요
- 키워드: DMA controller, cycle stealing, burst transfer

## 4-4. 입출력 방식 비교

| 구분 | Programmed I/O | Interrupt I/O | DMA |
|---|---|---|---|
| CPU 관여 | 매우 큼 | 중간 | 작음 |
| 방식 | CPU가 상태 계속 검사 | 장치가 CPU에 알림 | DMA 제어기가 직접 전송 |
| 장점 | 단순 | CPU 낭비 감소 | 대용량 전송 효율적 |
| 단점 | CPU 시간 낭비 | 인터럽트 오버헤드 | 구조 복잡, 버스 충돌 관리 필요 |
| 적합 | 단순/소량 입출력 | 비동기 장치 처리 | 디스크, 네트워크 등 대량 전송 |

## 4-5. 메모리 맵 입출력과 분리형 입출력

| 구분 | 메모리 맵 입출력 | 분리형 입출력 |
|---|---|---|
| 주소 공간 | 기억장치와 I/O가 같은 주소 공간 사용 | I/O 전용 주소 공간 사용 |
| 명령어 | 일반 메모리 접근 명령어 사용 | 별도 I/O 명령어 사용 |
| 장점 | 프로그래밍 단순 | 메모리 주소 공간 보존 |
| 단점 | 메모리 주소 공간 일부 사용 | 명령어 구조 별도 필요 |

### 서술형 답안 예시

```text
버스는 CPU, 기억장치, 입출력 장치 사이에서 정보를 전달하는 공통 통로이다. 주소 버스는 접근 대상의 주소를 전달하고, 데이터 버스는 실제 데이터를 전달하며, 제어 버스는 읽기와 쓰기 같은 동작 제어 신호를 전달한다. 입출력 방식에는 CPU가 장치 상태를 반복 확인하는 프로그램 제어 입출력, 장치가 준비되었을 때 CPU에 알리는 인터럽트 기반 입출력, DMA 제어기가 기억장치와 장치 사이의 데이터를 직접 전송하는 DMA 방식이 있다. 특히 DMA는 CPU 부담을 줄여 대용량 데이터 전송에 유리하다.
```

# 5. 인터럽트(Interrupt)

## 5-1. 핵심 정의

```text
인터럽트 = CPU가 현재 실행 중인 작업을 잠시 중단하고 긴급한 사건을 먼저 처리하도록 요청하는 신호
```

- 목적: CPU 효율 향상, 예외 상황 처리, 입출력 완료 알림
- 인터럽트가 없으면 CPU가 장치 상태를 계속 검사해야 함
- 인터럽트는 명령어 사이클 중 조건부로 처리됨

### 단답형 답안

| 용어 | 답안 |
|---|---|
| 인터럽트 | CPU가 현재 작업을 중단하고 특정 사건을 우선 처리하게 하는 요청 |
| ISR | 인터럽트 발생 시 실행되는 인터럽트 서비스 루틴 |
| 인터럽트 벡터 | 인터럽트 종류별 서비스 루틴의 시작 주소 정보 |
| 마스커블 인터럽트 | CPU가 허용/차단할 수 있는 인터럽트 |
| NMI | 차단할 수 없는 중요한 인터럽트 |

## 5-2. 인터럽트 처리 순서

```text
1. 인터럽트 요청 발생
2. CPU가 현재 명령어 실행 완료
3. 인터럽트 가능 여부와 우선순위 확인
4. 현재 상태 저장(PC, PSW 등)
5. 인터럽트 벡터를 통해 ISR 주소 확인
6. ISR 실행
7. 저장된 상태 복구
8. 원래 프로그램으로 복귀
```

핵심 암기:

```text
요청 → 현재 명령 완료 → 상태 저장 → ISR 실행 → 상태 복구 → 복귀
```

## 5-3. 인터럽트 종류

| 기준 | 종류 | 의미 |
|---|---|---|
| 발생 위치 | 내부 인터럽트 | CPU 내부 오류/예외, 잘못된 연산 등 |
| 발생 위치 | 외부 인터럽트 | 입출력 장치, 타이머, 전원 이상 등 외부 사건 |
| 차단 가능성 | 마스커블 인터럽트 | CPU가 무시하거나 지연 가능 |
| 차단 가능성 | 비마스커블 인터럽트(NMI) | 전원 이상 등 매우 중요한 요청, 차단 불가 |
| 발생 방식 | 소프트웨어 인터럽트 | 명령어 실행으로 의도적으로 발생 |
| 발생 방식 | 하드웨어 인터럽트 | 장치나 하드웨어가 발생 |

## 5-4. 인터럽트와 폴링 비교

| 구분 | 폴링 | 인터럽트 |
|---|---|---|
| 방식 | CPU가 장치 상태를 반복 확인 | 장치가 CPU에 요청 신호 보냄 |
| CPU 효율 | 낮음 | 높음 |
| 구현 | 단순 | 상대적으로 복잡 |
| 적합 | 단순 장치, 짧은 대기 | 비동기 입출력, 여러 장치 처리 |

## 5-5. 인터럽트, 트랩, 예외 비교

| 구분 | 인터럽트 | 트랩/소프트웨어 인터럽트 | 예외 |
|---|---|---|---|
| 발생 원인 | 외부 장치/하드웨어 사건 | 프로그램이 의도적으로 호출 | 명령 실행 중 오류/특수 상황 |
| 발생 시점 | 비동기적 | 동기적 | 동기적 |
| 예 | 키보드 입력, I/O 완료 | 시스템 콜 | 0으로 나누기, 페이지 폴트 |

### 서술형 답안 예시

```text
인터럽트는 CPU가 현재 프로그램을 실행하는 도중 입출력 완료나 오류 같은 사건이 발생했을 때 이를 우선 처리하도록 알리는 신호이다. CPU는 인터럽트 요청을 확인하면 현재 명령어를 마친 뒤 PC와 상태 레지스터 등을 저장하고 인터럽트 서비스 루틴으로 분기한다. 서비스 루틴 실행이 끝나면 저장된 상태를 복구하여 원래 프로그램을 계속 실행한다. 이 방식은 CPU가 장치 상태를 계속 검사하는 폴링보다 효율적이다.
```

# 6. 계산 관련 정의·공식 모음

## 6-1. 단위 변환

| 단위 | 값 |
|---|---:|
| 1 Byte | 8 bit |
| 1 KB | 2^10 Byte = 1024 Byte |
| 1 MB | 2^20 Byte |
| 1 GB | 2^30 Byte |
| 1 TB | 2^40 Byte |

## 6-2. 주소선 수 계산

```text
주소선 n개 → 2^n개의 주소
주소선 수 n = log2(주소 개수)
```

Byte 주소 지정이면:

```text
주소 개수 = 전체 Byte 수
주소선 수 = log2(전체 Byte 수)
```

Word 주소 지정이면:

```text
주소 개수 = 전체 용량 / 워드 크기
주소선 수 = log2(주소 개수)
```

## 6-3. 기억용량 계산

```text
전체 기억용량(bit) = 주소 개수 × 한 주소당 데이터 비트 수
전체 기억용량(Byte) = 전체 기억용량(bit) / 8
```

또는:

```text
전체 기억용량 = 2^(주소선 수) × 데이터선 폭
```

단, 데이터선 폭이 bit이면 결과도 bit 기준이다.

## 6-4. 자주 나오는 형태

| 문제 표현 | 해석 | 답 구하기 |
|---|---|---|
| `2^n × m bit` | 주소가 2^n개, 한 주소가 m bit | 주소선 n개, 데이터선 m개 |
| `1M × 8bit` | 주소 2^20개, 한 주소 8bit | 주소선 20개, 데이터선 8개, 용량 1MB |
| `주소선 16개, 데이터선 8개` | 2^16개 주소, 한 주소 8bit | 64KB |
| `64KB Byte 주소 지정` | 주소 개수 2^16개 | 주소선 16개 |

## 6-5. 빠른 암기표

| 용량(Byte 주소 지정) | 주소선 수 |
|---|---:|
| 1KB | 10 |
| 4KB | 12 |
| 16KB | 14 |
| 64KB | 16 |
| 256KB | 18 |
| 1MB | 20 |
| 4MB | 22 |
| 16MB | 24 |
| 64MB | 26 |
| 256MB | 28 |
| 1GB | 30 |
| 4GB | 32 |

## 6-6. 계산형 서술 답안 템플릿

```text
먼저 기억용량을 2의 거듭제곱 단위로 바꾼다. Byte 주소 지정 방식이므로 주소 하나가 1Byte를 가리킨다. 따라서 필요한 주소 개수는 전체 Byte 수와 같고, 주소선 n개는 2^n개의 주소를 표현할 수 있다. 그러므로 주소선 수는 log2(주소 개수)로 구한다.
```

# 7. 시험 직전 최종 비교표

| 헷갈리는 개념 | A | B | 핵심 차이 |
|---|---|---|---|
| Fetch vs Execute | 명령어를 가져옴 | 명령어를 실제 수행 | 가져오기 vs 실행 |
| Indirect vs Execute | 유효 주소 계산 | 연산/이동 수행 | 주소 찾기 vs 명령 수행 |
| PC vs IR | 다음 명령어 주소 | 현재 명령어 | 주소 vs 명령어 내용 |
| MAR vs MDR | 메모리 주소 | 메모리 데이터 | 주소 저장 vs 데이터 저장 |
| RAM vs ROM | 휘발성, 읽기/쓰기 | 비휘발성, 읽기 중심 | 실행 중 저장 vs 펌웨어 저장 |
| 주기억장치 vs 보조기억장치 | 실행 중 데이터 저장 | 장기 보관 | 빠르지만 휘발성 vs 느리지만 비휘발성 |
| 주소 버스 vs 데이터 버스 | 어디에 접근할지 | 무엇을 옮길지 | 주소 공간 vs 전송 폭 |
| Polling vs Interrupt | CPU가 계속 확인 | 장치가 CPU에 알림 | CPU 낭비 큼 vs 효율적 |
| Interrupt I/O vs DMA | CPU가 ISR로 처리 | DMA가 직접 데이터 전송 | 사건 알림 vs 대량 전송 |
| Maskable vs NMI | 차단 가능 | 차단 불가 | 일반 요청 vs 긴급 요청 |

# 8. 최종 체크리스트

- [ ] 제어장치가 직접 연산하는 장치가 아니라 제어 신호를 만드는 장치임을 설명할 수 있다.
- [ ] Fetch cycle, Indirect cycle, Execute cycle, Interrupt cycle의 차이를 말할 수 있다.
- [ ] PC, IR, MAR, MDR/MBR의 역할을 구분할 수 있다.
- [ ] RAM, ROM, 캐시, 보조기억장치의 차이를 설명할 수 있다.
- [ ] 주소선 수와 기억용량 계산에서 Byte/bit를 구분할 수 있다.
- [ ] 주소선 n개가 2^n개의 주소를 표현한다는 것을 활용할 수 있다.
- [ ] HDD와 SSD의 차이를 설명할 수 있다.
- [ ] 주소 버스, 데이터 버스, 제어 버스의 역할을 구분할 수 있다.
- [ ] Programmed I/O, Interrupt I/O, DMA를 비교할 수 있다.
- [ ] 인터럽트 처리 순서를 `상태 저장 → ISR → 복귀` 흐름으로 설명할 수 있다.
