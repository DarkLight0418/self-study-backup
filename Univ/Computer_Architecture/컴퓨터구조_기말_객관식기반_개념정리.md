# 컴퓨터구조 기말 객관식 기반 개념 정리

> 목적: 객관식 문제를 그대로 외우는 것이 아니라, **단답형·서술형으로 바뀌었을 때 설명 가능한 개념 구조**로 정리  
> 범위: 제어장치 · 기억장치 · 보조기억장치 · 버스와 입출력 · 인터럽트  
> 주의: 원문 문항과 선택지를 그대로 복제하지 않고, 출제 포인트를 개념 중심으로 재구성함.

---

## 0. 시험 직전 먼저 외울 핵심 문장

1. 제어장치는 명령어를 해독하고 필요한 제어 신호를 발생시켜 CPU 내부 동작을 조정한다.
2. 제어장치의 핵심 구성은 명령 레지스터, 명령 해독기, 제어 신호 발생기이다.
3. 고정 배선식 제어장치는 빠르지만 수정이 어렵고, 마이크로프로그램 방식은 유연하지만 상대적으로 느리다.
4. 마이크로프로그램은 제어 메모리에 저장된 마이크로명령어들의 집합이다.
5. 명령어 사이클은 보통 `인출 → 간접 → 실행 → 인터럽트` 단계로 이해한다.
6. 인출 사이클의 핵심은 `PC의 주소로 명령어를 가져와 IR에 넣는 것`이다.
7. 파이프라이닝은 하나의 일을 여러 단계로 나누어 겹쳐 실행함으로써 처리율을 높이는 기법이다.
8. 기억장치 계층은 위로 갈수록 빠르고 비싸며 용량이 작고, 아래로 갈수록 느리지만 싸고 용량이 크다.
9. RAM의 임의 접근은 어느 주소든 접근 시간이 거의 같다는 뜻이다.
10. SRAM은 빠르고 비싸며 캐시에, DRAM은 느리지만 집적도가 높아 주기억장치에 주로 사용된다.
11. ROM 계열은 전원이 꺼져도 내용이 유지되는 비휘발성 기억장치이다.
12. 캐시는 CPU와 주기억장치의 속도 차이를 줄이기 위해 자주 쓰는 데이터를 임시 저장한다.
13. 캐시의 핵심 원리는 지역성이다. 시간 지역성은 최근 사용한 데이터 재사용, 공간 지역성은 주변 데이터 접근 가능성을 뜻한다.
14. 직접 매핑은 단순하지만 충돌이 많고, 연관 매핑은 유연하지만 하드웨어 비용이 크다.
15. 가상기억장치는 실제 주기억장치보다 큰 기억공간을 사용하는 것처럼 보이게 하는 기법이다.
16. 메모리 인터리빙은 여러 메모리 모듈에 번갈아 접근하여 메모리 접근 효율을 높인다.
17. 디스크 접근 시간은 탐색 시간, 회전 지연 시간, 데이터 전송 시간의 합으로 본다.
18. RAID 0은 성능 중심, RAID 1은 미러링, RAID 5는 분산 패리티를 이용한다.
19. 버스는 CPU, 기억장치, 입출력장치 사이의 공통 통신 경로이다.
20. 데이터 버스는 실제 데이터, 주소 버스는 위치, 제어 버스는 읽기/쓰기 같은 제어 신호를 전달한다.
21. Programmed I/O는 CPU가 계속 확인하므로 단순하지만 CPU 낭비가 크다.
22. Interrupt-driven I/O는 장치가 필요할 때 CPU에게 알려 CPU 낭비를 줄인다.
23. DMA는 CPU 대신 DMA 제어기가 기억장치와 입출력장치 사이의 블록 전송을 담당한다.
24. 사이클 스틸링은 DMA가 버스 사용권을 잠시 가져와 CPU 사이클 일부를 사용하는 방식이다.
25. 인터럽트는 현재 실행 흐름을 잠시 중단하고 긴급한 사건을 처리한 뒤 원래 흐름으로 돌아가는 구조이다.
26. 인터럽트 처리에는 현재 상태 저장, 인터럽트 서비스 루틴 실행, 상태 복구가 필요하다.
27. 주소선이 `n`개이면 표현 가능한 주소 수는 `2^n`개이다.
28. 기억용량은 `주소 수 × 한 주소에 저장되는 데이터 크기`로 계산한다.
29. 칩 개수 계산은 먼저 칩 하나의 용량을 구하고, 목표 용량을 나누어 판단한다.
30. 서술형에서는 정의보다 `왜 필요한가 → 어떻게 동작하는가 → 장단점은 무엇인가` 순서로 답하면 안정적이다.

| 가상기억장치 | 페이지, 주소 변환, page fault | 가상기억장치 정의 | 실제 메모리보다 큰 프로그램 실행 원리 설명 |
| 보조기억장치 | 디스크 구조, 접근 시간, RAID | track/sector/cylinder | 디스크 접근 시간 구성 요소 설명 |
| 버스 | 주소/데이터/제어 버스, 동기/비동기 | 버스 종류 | 공통 버스 구조의 장단점 설명 |
| 입출력 | Programmed I/O, Interrupt I/O, DMA | 각 방식 정의 | CPU 관여 정도에 따른 I/O 방식 비교 |
| 인터럽트 | 벡터, 우선순위, ISR, 상태 저장 | 인터럽트 정의 | 인터럽트 처리 순서 설명 |

# Part 1. 제어장치와 명령어 실행

## 1.1 제어장치(Control Unit)

- 핵심: CPU 내부의 동작 순서를 지휘하는 장치
- 역할:
  - 명령어 해독
  - 제어 신호 생성
  - 레지스터, ALU, 기억장치, 입출력장치의 동작 조정
- 대표 구성:
  - 명령 레지스터(IR)
  - 명령 해독기(Instruction Decoder)
  - 제어 신호 발생기(Control Signal Generator)
  - 타이밍/클럭 관련 회로

### 단답형 암기

```text
제어장치 = 명령어 해독 + 제어 신호 발생 + CPU 동작 순서 제어
```

### 헷갈리기 쉬운 점

- 누산기, ALU는 CPU 구성 요소이지만 제어장치 자체의 핵심 구성으로 보기는 어렵다.
- 제어장치가 출력하는 것은 제어 신호이고, 제어장치가 입력으로 참고하는 것은 명령어, 플래그, 클럭 등이다.

---

## 1.2 제어장치에 입력되는 정보

- 명령어 레지스터의 opcode
- 플래그/상태 레지스터 값
- 클럭 신호
- 인터럽트 요청 신호
- 실행 단계 정보

### 구조

```text
IR(opcode) + Flag + Clock + Interrupt
        ↓
    Control Unit
        ↓
  제어 신호 발생
```

### 시험 포인트

- `CPU 내부 제어 신호`는 보통 제어장치의 출력 결과로 보는 것이 자연스럽다.
- 제어장치는 입력 정보를 보고 다음 마이크로동작 또는 제어 신호를 결정한다.

---

## 1.3 고정 배선식 제어장치 vs 마이크로프로그램 제어장치

| 구분 | 고정 배선식 제어 | 마이크로프로그램 제어 |
|---|---|---|
| 구현 | 논리회로로 직접 구현 | 제어 메모리에 저장된 마이크로명령어 실행 |
| 속도 | 빠름 | 상대적으로 느림 |
| 변경 | 수정 어려움 | 수정·확장 비교적 쉬움 |
| 비용/복잡도 | 명령어가 복잡할수록 회로 복잡 | 복잡한 명령어 집합에 유리 |
| 적합 | 단순하고 빠른 CPU, RISC 경향 | 복잡한 명령어, CISC 경향 |
| 핵심 암기 | HW | SW에 가까운 펌웨어 구조 |

### 서술형 답안 뼈대

```text
고정 배선식 제어장치는 제어 신호를 논리회로로 직접 발생시키기 때문에 속도가 빠르다.
하지만 명령어 구조가 바뀌면 회로를 다시 설계해야 하므로 수정과 확장이 어렵다.
반면 마이크로프로그램 제어장치는 제어 메모리에 저장된 마이크로명령어를 이용해 제어 신호를 발생시키므로 유연하고 유지보수가 쉽다.
다만 제어 메모리를 읽는 과정이 필요하므로 고정 배선식보다 느릴 수 있다.
```

---

## 1.4 마이크로프로그램과 마이크로명령어

- 마이크로프로그램:
  - CPU 제어 동작을 작은 단위의 명령들로 표현한 프로그램
  - 제어 메모리(Control Memory)에 저장
  - 일반적으로 ROM 또는 펌웨어 성격의 저장장치에 위치
- 마이크로명령어:
  - 하나 이상의 마이크로연산을 지시하는 제어 단위
  - 제어 신호와 다음 마이크로명령어 주소 정보를 포함할 수 있음
- 마이크로연산:
  - 레지스터 전송, ALU 연산, 메모리 읽기/쓰기처럼 CPU 내부에서 일어나는 가장 작은 동작

### 구조

```text
명령어(opcode)
   ↓
마이크로프로그램 시작 주소 결정
   ↓
마이크로명령어 실행
   ↓
제어 신호 발생
   ↓
마이크로연산 수행
```

---

## 1.5 수평적 마이크로프로그래밍 vs 수직적 마이크로프로그래밍

| 구분 | 수평적 방식 | 수직적 방식 |
|---|---|---|
| 제어 비트 | 제어 신호와 거의 1:1 대응 | 제어 필드를 인코딩하여 사용 |
| 명령어 길이 | 김 | 짧음 |
| 해독 과정 | 적거나 단순 | 해독 필요 |
| 속도 | 빠름 | 상대적으로 느림 |
| 하드웨어 비용 | 제어 메모리 용량 큼 | 제어 메모리 절약 |
| 암기 | 비트 많음, 빠름 | 압축됨, 해독 필요 |

### 단답형

```text
수평적 마이크로명령어 = 제어 신호를 넓은 비트 필드로 직접 표현하는 방식
수직적 마이크로명령어 = 제어 정보를 인코딩하여 짧게 표현하는 방식
```

---

## 1.6 명령어 사이클

- 명령어 사이클: CPU가 하나의 명령어를 가져와 실행하고 필요한 처리를 마칠 때까지의 과정
- 대표 단계:
  1. 인출 사이클(fetch cycle)
  2. 간접 사이클(indirect cycle)
  3. 실행 사이클(execute cycle)
  4. 인터럽트 사이클(interrupt cycle)

### 기본 흐름

```text
Fetch → Decode → Operand 준비 → Execute → Interrupt 확인
```

조금 더 시험형으로 쓰면:

```text
인출 사이클 → 간접 사이클(필요 시) → 실행 사이클 → 인터럽트 사이클(필요 시)
```

---

## 1.7 인출 사이클(fetch cycle)

- 핵심: 기억장치에서 다음에 실행할 명령어를 읽어 IR에 저장
- 대표 마이크로연산:

```text
T1: MAR ← PC
T2: MBR/MDR ← M[MAR], PC ← PC + 1
T3: IR ← MBR/MDR
```

### 레지스터 의미

| 레지스터 | 의미 |
|---|---|
| PC | 다음 명령어 주소 저장 |
| MAR | 접근할 기억장치 주소 저장 |
| MBR/MDR | 기억장치에서 읽거나 쓸 데이터 임시 저장 |
| IR | 현재 실행할 명령어 저장 |

### 단답형

```text
인출 사이클 = PC가 가리키는 주소의 명령어를 메모리에서 읽어 IR에 저장하는 단계
```

---

## 1.8 간접 사이클(indirect cycle)

- 핵심: 명령어의 주소 필드가 실제 데이터 주소가 아니라, 실제 주소가 들어 있는 위치를 가리킬 때 필요
- 사용 조건: 간접 주소 지정 방식
- 흐름:

```text
명령어의 주소 필드 → 메모리 접근 → 실제 유효 주소 획득
```

### 암기

```text
간접 사이클 = 주소의 주소를 따라가서 실제 주소를 구하는 단계
```

---

## 1.9 실행 사이클(execute cycle)

- 핵심: 명령어가 요구하는 실제 연산 수행
- 예:
  - 산술/논리 연산
  - 메모리 읽기/쓰기
  - 분기
  - 입출력

### 단답형

```text
실행 사이클 = 해독된 명령어에 따라 실제 연산이나 데이터 이동을 수행하는 단계
```

---

## 1.10 인터럽트 사이클(interrupt cycle)

- 핵심: 인터럽트 요청이 있으면 현재 실행 위치를 저장하고 인터럽트 처리 루틴으로 이동
- 흐름:

```text
인터럽트 요청 확인
→ 현재 PC/상태 저장
→ 인터럽트 서비스 루틴 주소를 PC에 적재
→ ISR 실행
→ 원래 프로그램으로 복귀
```

### 암기

```text
인터럽트 사이클 = 하던 일을 저장하고 급한 일을 처리한 뒤 돌아오기 위한 준비 단계
```

---

## 1.11 파이프라이닝(pipelining)

- 핵심: 하나의 명령어 실행을 여러 단계로 나누고, 여러 명령어를 겹쳐 처리
- 목적: 처리율 향상
- 비유:

```text
세탁 → 건조 → 접기
한 벌이 끝날 때까지 기다리지 않고 단계별로 겹쳐 처리
```

### 장점

- 전체 처리율 증가
- CPU 자원 활용률 향상

### 주의

- 단일 명령어 하나의 지연시간 자체가 반드시 줄어드는 것은 아니다.
- 데이터 hazard, 제어 hazard, 구조 hazard가 발생할 수 있다.

# Part 2. 기억장치

## 2.1 기억장치 계층 구조

| 계층 | 속도 | 용량 | 가격/bit | 휘발성 | 예 |
|---|---:|---:|---:|---|---|
| 레지스터 | 가장 빠름 | 가장 작음 | 가장 비쌈 | 휘발성 | PC, IR, ACC |
| 캐시 | 빠름 | 작음 | 비쌈 | 휘발성 | L1/L2/L3 cache |
| 주기억장치 | 보통 | 중간 | 보통 | 휘발성 | DRAM |
| 보조기억장치 | 느림 | 큼 | 저렴 | 비휘발성 | SSD, HDD |

### 핵심 원리

```text
위로 갈수록: 빠름 / 작음 / 비쌈
아래로 갈수록: 느림 / 큼 / 저렴
```

---

## 2.2 기억장치 성능 용어

| 용어 | 의미 | 시험식 표현 |
|---|---|---|
| 접근 시간(access time) | 주소를 준 뒤 데이터가 나올 때까지의 시간 | 읽기 요청 → 데이터 도착 |
| 기억장치 사이클 시간 | 다음 접근이 가능해질 때까지의 시간 | 접근 시간 + 회복 시간 |
| 대역폭(bandwidth) | 단위 시간당 전송 가능한 데이터 양 | 초당 몇 byte/bit 전송 |
| 지연시간(latency) | 요청 후 실제 응답까지 기다리는 시간 | 기다림 중심 |

---

## 2.3 RAM

- RAM: Random Access Memory
- 의미:
  - 주소 위치와 관계없이 거의 같은 시간에 접근 가능
  - 읽기와 쓰기 가능
  - 일반적으로 휘발성

### 단답형

```text
RAM = 임의 접근이 가능하고 읽기/쓰기가 가능한 주기억장치 계열
```

---

## 2.4 SRAM vs DRAM

| 구분 | SRAM | DRAM |
|---|---|---|
| 저장 원리 | 플립플롭 | 축전기/커패시터 |
| 속도 | 빠름 | 느림 |
| 가격 | 비쌈 | 저렴 |
| 집적도 | 낮음 | 높음 |
| refresh | 필요 없음 | 필요함 |
| 주 용도 | 캐시 메모리 | 주기억장치 |
| 암기 | Static = 안정적, 빠름 | Dynamic = 계속 새로고침 |

### 서술형 포인트

```text
SRAM은 플립플롭을 사용해 refresh가 필요 없고 속도가 빠르지만 비싸고 집적도가 낮다.
DRAM은 축전기에 전하를 저장하므로 주기적인 refresh가 필요하지만 구조가 단순하여 집적도가 높고 저렴하다.
따라서 SRAM은 캐시, DRAM은 주기억장치에 주로 사용된다.
```

ROM = 비휘발성 + 주로 읽기 중심 + 펌웨어 저장에 적합
```

| 구분 | 저장 방식 | 예시 |
|---|---|---|
| Big-endian | 큰 자리 byte를 낮은 주소에 저장 | 사람이 숫자 쓰는 순서와 비슷 |

엔디언 = 여러 바이트로 구성된 데이터를 메모리에 어떤 순서로 저장할지 정하는 방식
```

## 2.7 캐시 메모리

- 목적: CPU와 주기억장치의 속도 차이 완화
- 원리: 자주 쓰거나 곧 쓸 가능성이 높은 데이터를 빠른 메모리에 임시 저장
- 핵심 용어:
  - cache hit: 필요한 데이터가 캐시에 있음
  - cache miss: 필요한 데이터가 캐시에 없음
  - hit ratio: 전체 접근 중 hit 비율
  - miss penalty: miss 발생 시 추가로 걸리는 시간

### 구조

```text
CPU → Cache 확인 → 있으면 바로 사용
             → 없으면 Main Memory에서 가져옴
```

---

## 2.8 지역성(locality)

| 종류 | 의미 | 예 |
|---|---|---|
| 시간 지역성 | 최근 사용한 데이터를 다시 사용할 가능성 | 반복문 변수, 최근 명령어 |
| 공간 지역성 | 사용한 데이터 근처를 곧 사용할 가능성 | 배열 순차 접근 |

### 암기

```text
캐시는 지역성이 있기 때문에 효과가 있다.
```

---

## 2.9 캐시 매핑 방식

| 구분 | 직접 매핑 | 완전 연관 매핑 | 세트 연관 매핑 |
|---|---|---|---|
| 위치 | 메모리 블록이 들어갈 캐시 위치 고정 | 어디든 가능 | 정해진 set 안에서 선택 |
| 장점 | 단순, 빠름, 저렴 | 충돌 적음, 유연 | 직접/연관의 절충 |
| 단점 | 충돌 miss 많음 | 비교 회로 비용 큼 | 구조가 중간 정도 복잡 |
| 암기 | 자리 고정 | 아무 자리 | 정해진 묶음 안에서 자유 |

### 단답형

```text
직접 매핑 = 주기억장치 블록이 들어갈 캐시 라인이 하나로 정해지는 방식
연관 매핑 = 주기억장치 블록이 캐시의 어느 라인에도 들어갈 수 있는 방식
세트 연관 매핑 = 캐시를 여러 set으로 나누고, 해당 set 안에서 연관 매핑하는 방식
```

---

## 2.10 캐시 교체 정책

| 정책 | 의미 | 특징 |
|---|---|---|
| LRU | 가장 오랫동안 사용하지 않은 블록 교체 | 지역성 반영, 자주 출제 |
| FIFO | 먼저 들어온 블록 먼저 교체 | 단순 |
| LFU | 사용 횟수가 가장 적은 블록 교체 | 카운터 필요 |
| Random | 무작위 교체 | 단순하지만 예측 어려움 |

### 암기

```text
LRU = 오래 안 쓴 것부터 버린다.
FIFO = 먼저 들어온 것부터 버린다.
```

---

## 2.11 캐시 쓰기 정책

| 구분 | Write-through | Write-back |
|---|---|---|
| 동작 | 캐시에 쓸 때 주기억장치도 즉시 갱신 | 캐시만 먼저 갱신, 교체 시 주기억장치 반영 |
| 장점 | 메모리 일관성 좋음 | 쓰기 횟수 감소, 성능 좋음 |
| 단점 | 쓰기마다 주기억장치 접근, 느림 | 일관성 관리 복잡 |
| 암기 | 바로 같이 씀 | 나중에 몰아서 씀 |

### 서술형 포인트

```text
write-through는 캐시와 주기억장치를 동시에 갱신하므로 데이터 일관성은 높지만 메모리 접근이 많아 성능 저하가 생길 수 있다.
write-back은 캐시에 먼저 쓰고 해당 블록이 교체될 때 주기억장치에 반영하므로 쓰기 성능은 좋지만 일관성 관리가 복잡하다.
```

## 2.12 가상기억장치

- 핵심: 실제 주기억장치보다 큰 기억공간을 사용하는 것처럼 보이게 하는 기법
- 목적:
  - 큰 프로그램 실행 가능
  - 다중 프로그래밍 지원
  - 메모리 관리 효율 향상
- 기반:
  - 보조기억장치 일부를 주기억장치처럼 활용
  - 필요한 부분만 주기억장치에 적재

### 주요 용어

| 용어 | 의미 |
|---|---|
| page | 가상주소 공간의 고정 크기 블록 |
| frame | 물리 메모리의 고정 크기 블록 |
| page table | 가상 페이지와 물리 프레임의 대응표 |
| page fault | 필요한 페이지가 주기억장치에 없을 때 발생 |
| TLB | 주소 변환을 빠르게 하기 위한 캐시 |

### 단답형

```text
가상기억장치 = 보조기억장치를 이용해 실제 메모리보다 큰 논리적 메모리 공간을 제공하는 기법
```

### 주의

- 가상기억장치는 물리적 RAM 용량 자체를 늘리는 것이 아니다.
- 너무 자주 page fault가 발생하면 성능이 급격히 떨어진다.

## 2.13 메모리 인터리빙

- 핵심: 여러 메모리 모듈에 주소를 번갈아 배치하여 병렬적으로 접근
- 목적: 메모리 접근 효율 증가
- 구조:

```text
주소 0 → 모듈 0
주소 1 → 모듈 1
주소 2 → 모듈 2
주소 3 → 모듈 3
주소 4 → 모듈 0 ...
```

### 단답형

```text
메모리 인터리빙 = 여러 메모리 모듈을 번갈아 접근하여 메모리 대역폭을 높이는 방식
```

# Part 3. 보조기억장치

## 3.1 보조기억장치의 역할

- 전원이 꺼져도 데이터를 보존
- 대용량 데이터 저장
- 주기억장치보다 느리지만 단위 용량당 가격이 저렴

### 대표 종류

| 종류 | 특징 |
|---|---|
| HDD | 자기 디스크, 기계적 움직임 있음 |
| SSD | 플래시 메모리 기반, 기계적 움직임 없음 |
| Optical Disk | CD/DVD/Blu-ray 등 빛을 이용 |
| Magnetic Tape | 순차 접근, 백업용 |

---

## 3.2 자기 디스크 구조

| 용어 | 의미 |
|---|---|
| platter | 실제 데이터가 저장되는 원판 |
| track | 원판 위의 동심원 형태 저장 경로 |
| sector | track을 나눈 최소 저장 단위 |
| cylinder | 여러 platter에서 같은 반지름의 track 집합 |
| block | 운영체제나 저장장치가 한 번에 다루는 데이터 단위 |

### 구조 암기

```text
디스크 표면 → 트랙 → 섹터 → 블록
같은 반지름의 트랙 묶음 = 실린더
```

---

## 3.3 디스크 접근 시간

```text
디스크 접근 시간 = 탐색 시간 + 회전 지연 시간 + 데이터 전송 시간
```

| 구성 요소 | 의미 |
|---|---|
| 탐색 시간(seek time) | 헤드를 원하는 트랙으로 이동시키는 시간 |
| 회전 지연 시간(rotational latency) | 원하는 섹터가 헤드 아래로 올 때까지 기다리는 시간 |
| 전송 시간(transfer time) | 실제 데이터를 읽거나 쓰는 시간 |

### 단답형

```text
탐색 시간 = 트랙 찾는 시간
회전 지연 = 섹터가 돌아오길 기다리는 시간
전송 시간 = 실제 데이터 이동 시간
```

---

## 3.4 디스크 스케줄링

| 방식 | 의미 | 특징 |
|---|---|---|
| FCFS | 요청 순서대로 처리 | 공정하지만 느릴 수 있음 |
| SSTF | 현재 헤드에서 가장 가까운 요청 먼저 처리 | 평균 탐색 시간 감소, starvation 가능 |
| SCAN | 한 방향으로 이동하며 처리 후 반대 방향 | 엘리베이터 방식 |
| C-SCAN | 한 방향으로만 처리하고 끝에서 처음으로 이동 | 대기 시간 균등화 |
| LOOK | 요청이 있는 범위까지만 이동 | SCAN 개선 |
| C-LOOK | C-SCAN의 개선형 | 불필요한 끝 이동 감소 |

## 3.5 SSD와 Flash Memory

- SSD:
  - 플래시 메모리 기반 보조기억장치
  - 기계적 움직임이 없어 HDD보다 접근 지연이 작음
  - 충격에 강하고 조용함
- 주의:
  - 쓰기 횟수 제한 존재
  - wear leveling 필요

### Flash 저장 방식

| 구분 | 저장 bit 수 | 특징 |
|---|---:|---|
| SLC | 1bit/cell | 빠르고 안정적, 비쌈 |
| MLC | 2bit/cell | 중간 |
| TLC | 3bit/cell | 용량/가격 유리 |
| QLC | 4bit/cell | 고용량, 내구성 낮음 |

## 3.6 RAID

| 구분 | 핵심 | 장점 | 단점 |
|---|---|---|---|
| RAID 0 | striping | 속도 향상 | 장애 복구 불가 |
| RAID 1 | mirroring | 신뢰성 높음 | 저장 효율 낮음 |
| RAID 5 | 분산 패리티 | 성능과 신뢰성 절충 | 쓰기 부담, 최소 3개 디스크 |
| RAID 6 | 이중 패리티 | 두 디스크 장애까지 대응 | 계산/쓰기 부담 증가 |

### 단답형

```text
RAID 0 = 성능 중심
RAID 1 = 복제 중심
RAID 5 = 분산 패리티 중심
```

# Part 4. 버스와 입출력

## 4.1 버스(Bus)

- 핵심: CPU, 기억장치, 입출력장치를 연결하는 공통 통신 경로
- 버스의 3요소:

| 종류 | 역할 |
|---|---|
| 데이터 버스 | 실제 데이터 이동 |
| 주소 버스 | 접근할 장치나 기억장치 위치 지정 |
| 제어 버스 | 읽기/쓰기, 인터럽트, 클럭, 버스 요청 등 제어 신호 전달 |

### 단답형

```text
버스 = 컴퓨터 내부 장치들이 데이터, 주소, 제어 신호를 주고받는 공통 통로
```

---

## 4.2 주소 버스와 기억용량

- 주소 버스 선 수가 많을수록 더 많은 주소를 표현 가능
- 주소선 `n`개:

```text
주소 개수 = 2^n
```

- byte-addressable이면:

```text
최대 주소 지정 용량 = 2^n byte
```

### 예시

```text
주소선 16개 → 2^16개 주소 → 65,536 byte → 64KB
주소선 20개 → 2^20개 주소 → 1,048,576 byte → 1MB
주소선 30개 → 2^30개 주소 → 1GB
```

---

## 4.3 동기식 버스 vs 비동기식 버스

| 구분 | 동기식 버스 | 비동기식 버스 |
|---|---|---|
| 기준 | 공통 클럭 | handshaking 신호 |
| 속도 | 빠름 | 상대적으로 느림 |
| 설계 | 단순 | 복잡 |
| 유연성 | 낮음 | 높음 |
| 적합 | 비슷한 속도의 장치 | 속도 차이가 큰 장치 |
| 암기 | clock 중심 | request/ack 중심 |

### 비동기식 흐름

```text
요청 신호(request) → 응답 신호(acknowledge) → 데이터 전송
```

---

## 4.4 버스 중재(bus arbitration)

- 목적: 여러 장치가 동시에 버스를 사용하려 할 때 우선순위 결정
- 방식:

| 방식 | 특징 |
|---|---|
| Daisy chain | 우선순위가 물리적 연결 순서에 따라 결정 |
| Polling | 중재기가 장치를 순서대로 확인 |
| Independent request | 각 장치가 독립 요청선 사용, 빠르지만 회선 많음 |
| Distributed arbitration | 중앙 중재기 없이 각 장치가 판단 |

### 단답형

```text
버스 중재 = 여러 장치의 버스 사용 요청 중 누가 먼저 사용할지 결정하는 과정
```

---

## 4.5 입출력 인터페이스

- 역할: CPU와 주변장치 사이의 속도·형식 차이를 조정
- 주요 레지스터:

| 레지스터 | 의미 |
|---|---|
| 데이터 레지스터 | 전송할 데이터 저장 |
| 상태 레지스터 | 장치 준비 상태, 오류 상태 표시 |
| 제어 레지스터 | 장치 동작 명령 저장 |

---

## 4.6 Memory-mapped I/O vs Isolated I/O

| 구분 | Memory-mapped I/O | Isolated I/O |
|---|---|---|
| 주소 공간 | 메모리와 I/O가 같은 주소 공간 사용 | I/O 전용 주소 공간 사용 |
| 명령어 | 일반 메모리 명령어 사용 가능 | 별도 I/O 명령어 필요 |
| 장점 | 프로그래밍 단순 | 메모리 주소 공간 절약 |
| 단점 | 메모리 주소 공간 일부 사용 | 명령어/제어 구조 별도 필요 |
| 암기 | I/O도 메모리처럼 주소 부여 | I/O는 따로 분리 |

---

## 4.7 Programmed I/O

- CPU가 장치 상태를 계속 확인하며 직접 데이터 전송
- 특징:
  - 구조 단순
  - 구현 쉬움
  - CPU가 계속 대기/확인하므로 비효율적

### 흐름

```text
CPU가 상태 레지스터 확인
→ 준비 완료면 데이터 전송
→ 다시 상태 확인 반복
```

### 단답형

```text
Programmed I/O = CPU가 입출력장치 상태를 직접 검사하고 데이터 전송을 수행하는 방식
```

---

## 4.8 Interrupt-driven I/O

- 입출력장치가 준비되면 CPU에게 인터럽트로 알림
- 특징:
  - CPU가 계속 polling하지 않아도 됨
  - CPU는 다른 작업 수행 가능
  - 인터럽트 처리 오버헤드 존재

### 흐름

```text
CPU가 I/O 명령 시작
→ CPU는 다른 작업 수행
→ 장치 준비 완료 시 인터럽트 요청
→ ISR에서 데이터 처리
```

### 단답형

```text
Interrupt-driven I/O = 입출력장치가 준비 완료를 인터럽트로 알려 CPU가 필요한 순간에 처리하는 방식
```

---

## 4.9 DMA

- DMA: Direct Memory Access
- 핵심: CPU를 거치지 않고 DMA 제어기가 주기억장치와 입출력장치 사이의 데이터 블록 전송 담당
- CPU 역할:
  - DMA 시작 주소 지정
  - 전송할 데이터 양 지정
  - 읽기/쓰기 방향 지정
  - 전송 시작 명령
  - 완료 인터럽트 수신

### 흐름

```text
CPU가 DMA 제어기에 전송 정보 설정
→ DMA 제어기가 버스 사용권 획득
→ 메모리 ↔ I/O 장치 직접 전송
→ 완료 후 CPU에 인터럽트
```

### 장점

- 대량 데이터 전송에 효율적
- CPU 부담 감소
- 입출력 성능 향상

---

## 4.10 DMA 전송 방식

| 방식 | 의미 | 특징 |
|---|---|---|
| Burst mode | 버스를 일정 시간 독점하여 블록 전송 | 빠르지만 CPU 대기 큼 |
| Cycle stealing | CPU 사이클 사이에 한 워드씩 전송 | CPU 방해 적지만 전송 느림 |
| Transparent mode | CPU가 버스를 쓰지 않을 때만 전송 | CPU 영향 최소, 전송 시간 길어짐 |

### 단답형

```text
사이클 스틸링 = DMA가 CPU의 버스 사이클 일부를 잠시 빼앗아 데이터 전송에 사용하는 방식
```

---

## 4.11 Channel I/O와 IOP

- Channel I/O:
  - 입출력 전용 프로세서 또는 채널이 입출력 작업을 독립적으로 수행
  - 대형 컴퓨터에서 CPU 부담 감소 목적
- IOP:
  - Input/Output Processor
  - 입출력 프로그램을 실행하여 복잡한 입출력 제어 수행

### 비교

| 구분 | DMA | Channel I/O/IOP |
|---|---|---|
| 역할 | 데이터 블록 전송 중심 | 입출력 명령 처리까지 담당 |
| 지능성 | 낮음 | 높음 |
| CPU 부담 | 감소 | 더 크게 감소 |
| 사용 | 일반 시스템 | 대형/고성능 시스템 |

---

# Part 5. 인터럽트

## 5.1 인터럽트의 정의

- 인터럽트: CPU가 현재 실행 중인 프로그램을 잠시 중단하고, 더 긴급하거나 필요한 사건을 먼저 처리하도록 하는 신호
- 목적:
  - 입출력 완료 처리
  - 오류 처리
  - 타이머 처리
  - 시스템 호출 처리

### 단답형

```text
인터럽트 = 현재 실행 흐름을 일시 중단하고 특정 사건을 처리한 뒤 원래 흐름으로 복귀하게 하는 메커니즘
```

---

## 5.2 인터럽트 처리 순서

```text
1. 현재 명령어 실행 완료
2. 인터럽트 요청 확인
3. 인터럽트 허용 여부와 우선순위 판단
4. PC, PSW 등 현재 상태 저장
5. 인터럽트 벡터를 통해 ISR 주소 확인
6. ISR 실행
7. 저장된 상태 복구
8. 원래 프로그램으로 복귀
```

### 핵심 암기

```text
저장 → 이동 → 처리 → 복구 → 복귀
```

---

## 5.3 인터럽트 관련 용어

| 용어 | 의미 |
|---|---|
| ISR | 인터럽트 서비스 루틴, 실제 처리 코드 |
| Interrupt vector | ISR 시작 주소를 찾기 위한 정보 |
| Interrupt vector table | 인터럽트 종류별 ISR 주소 저장 테이블 |
| PSW | CPU 상태 정보 저장 레지스터 |
| Maskable interrupt | 비활성화 가능 인터럽트 |
| Non-maskable interrupt | 비활성화하기 어려운 긴급 인터럽트 |
| Nested interrupt | ISR 실행 중 더 높은 우선순위 인터럽트 허용 |

---

## 5.4 인터럽트 종류

| 구분 | 의미 | 예 |
|---|---|---|
| 외부 인터럽트 | CPU 외부 장치에서 발생 | 입출력 완료, 타이머 |
| 내부 인터럽트/예외 | 명령 실행 중 CPU 내부에서 발생 | 0으로 나눔, overflow |
| 소프트웨어 인터럽트 | 명령어에 의해 의도적으로 발생 | 시스템 콜 |

---

## 5.5 인터럽트 우선순위 결정 방식

| 방식 | 특징 |
|---|---|
| Polling | CPU가 장치를 순서대로 확인 |
| Daisy chain | 연결 순서에 따라 우선순위 결정 |
| Parallel priority | 우선순위 회로로 빠르게 결정 |
| Software priority | 소프트웨어적으로 우선순위 판단 |

### 단답형

```text
인터럽트 우선순위 = 여러 인터럽트가 동시에 발생했을 때 먼저 처리할 인터럽트를 결정하는 기준
```

# Part 6. 계산 문제 정리

## 6.1 주소선 수와 기억용량

### 기본 공식

```text
주소선 n개 → 주소 개수 = 2^n
byte-addressable이면 용량 = 2^n byte
word-addressable이면 용량 = 2^n × word 크기
```

### 예시 1

```text
주소선 16개, byte-addressable
→ 2^16 byte
→ 65,536 byte
→ 64KB
```

### 예시 2

```text
주소선 20개, word 크기 4byte
→ 주소 개수 = 2^20 word
→ 전체 용량 = 2^20 × 4byte
→ 4MB
```

### 주의

- 문제에서 `byte 단위 주소`인지 `word 단위 주소`인지 반드시 확인한다.
- 데이터 버스 폭은 한 번에 전송 가능한 데이터 크기와 관련된다.

---

## 6.2 기억장치 칩 개수 계산

### 기본 순서

```text
1. 칩 하나의 용량 계산
2. 목표 전체 용량 계산
3. 목표 용량 ÷ 칩 하나 용량
4. 데이터 폭 확장이 필요한지 확인
```

### 예시

```text
256 × 8 RAM 칩 하나
= 256개 주소 × 8bit
= 256byte

2KB 메모리 구성
= 2048byte ÷ 256byte
= 8개
```

---

## 6.3 버스 대역폭 계산

### 공식

```text
버스 대역폭 = 한 번에 전송하는 데이터 크기 × 초당 전송 횟수
```

### 예시

```text
데이터 버스 32bit, 클럭 100MHz, 1클럭당 1회 전송
→ 32bit = 4byte
→ 4byte × 100,000,000
→ 400MB/s
```

---

## 6.4 디스크 용량 계산

### 공식

```text
디스크 용량 = 표면 수 × 트랙 수 × 섹터 수 × 섹터당 byte 수
```

### 예시

```text
표면 2개, 표면당 트랙 1,000개, 트랙당 섹터 100개, 섹터당 512byte
→ 2 × 1,000 × 100 × 512
→ 102,400,000 byte
```

---

## 6.5 디스크 접근 시간 계산

### 공식

```text
접근 시간 = 탐색 시간 + 회전 지연 시간 + 데이터 전송 시간
```

### 예시

```text
탐색 시간 8ms, 회전 지연 4ms, 전송 시간 2ms
→ 전체 접근 시간 = 14ms
```

---

## 6.6 평균 메모리 접근 시간 AMAT

### 공식

```text
AMAT = cache hit time + miss rate × miss penalty
```

또는:

```text
AMAT = hit ratio × cache access time + miss ratio × miss 처리 시간
```

### 예시

```text
hit time = 10ns
miss rate = 5%
miss penalty = 100ns

AMAT = 10ns + 0.05 × 100ns
     = 15ns
```

| 용어 | 단답형 답안 |
|---|---|
| 제어장치 | 명령어를 해독하고 제어 신호를 발생시켜 CPU 내부 동작을 제어하는 장치 |
| 명령어 레지스터 | 현재 실행할 명령어를 저장하는 레지스터 |

| MAR | 접근할 기억장치 주소를 저장하는 레지스터 |
| MBR/MDR | 기억장치와 CPU 사이에서 이동하는 데이터를 임시 저장하는 레지스터 |
| 마이크로프로그램 | CPU 제어 동작을 수행하기 위한 마이크로명령어들의 집합 |

| 인출 사이클 | 메모리에서 명령어를 읽어 IR에 저장하는 단계 |

| 실행 사이클 | 명령어가 요구하는 실제 연산을 수행하는 단계 |
| 인터럽트 사이클 | 인터럽트 처리를 위해 현재 상태를 저장하고 ISR로 이동하는 단계 |
| 캐시 메모리 | CPU와 주기억장치 사이의 속도 차이를 줄이기 위한 고속 기억장치 |
| 지역성 | 프로그램이 최근 사용한 데이터나 그 주변 데이터를 다시 사용할 가능성 |
| 가상기억장치 | 보조기억장치를 활용해 실제보다 큰 메모리를 사용하는 것처럼 보이게 하는 기법 |
| 페이지 폴트 | 필요한 페이지가 주기억장치에 없어 보조기억장치에서 가져와야 하는 상황 |
| 메모리 인터리빙 | 여러 메모리 모듈을 번갈아 접근하여 메모리 처리율을 높이는 방식 |
| 버스 | 컴퓨터 내부 장치들이 신호와 데이터를 주고받는 공통 전송 경로 |
| DMA | CPU 대신 DMA 제어기가 메모리와 입출력장치 사이의 데이터 전송을 수행하는 방식 |
| 인터럽트 | 현재 실행을 잠시 중단하고 특정 사건을 처리하도록 CPU에 알리는 신호 |
| ISR | 인터럽트 발생 시 실행되는 처리 루틴 |

# Part 8. 서술형 예상 문제와 답안 구조

## 8.1 고정 배선식 제어장치와 마이크로프로그램 제어장치를 비교하시오.

답안 구조:

```text
1. 제어장치의 역할 제시
2. 고정 배선식: 논리회로 기반, 빠름, 수정 어려움
3. 마이크로프로그램: 제어 메모리 기반, 유연함, 상대적으로 느림
4. 명령어 집합이 단순하면 고정 배선식, 복잡하면 마이크로프로그램 방식이 유리함
```

---

## 8.2 인출 사이클의 동작을 레지스터 중심으로 설명하시오.

답안 구조:

```text
1. PC에는 다음 명령어 주소가 들어 있다.
2. PC 값이 MAR로 전달된다.
3. 메모리에서 해당 주소의 명령어가 MBR/MDR로 읽힌다.
4. PC는 다음 명령어를 가리키도록 증가한다.
5. MBR/MDR의 명령어가 IR에 저장된다.
```

---

## 8.3 SRAM과 DRAM을 비교하시오.

답안 구조:

```text
SRAM은 플립플롭 기반이라 refresh가 필요 없고 빠르지만 비싸고 집적도가 낮다.
DRAM은 커패시터 기반이라 refresh가 필요하지만 저렴하고 집적도가 높다.
따라서 SRAM은 캐시, DRAM은 주기억장치에 주로 사용된다.
```

---

## 8.4 캐시 메모리가 성능을 향상시키는 원리를 설명하시오.

답안 구조:

```text
캐시는 CPU와 주기억장치 사이의 속도 차이를 줄이기 위한 고속 기억장치이다.
프로그램은 시간 지역성과 공간 지역성을 가지므로 최근 사용한 데이터나 인접 데이터를 다시 사용할 가능성이 높다.
캐시는 이러한 데이터를 미리 또는 임시로 저장하여 cache hit가 발생하면 주기억장치 접근보다 빠르게 데이터를 제공한다.
따라서 평균 메모리 접근 시간이 감소하고 CPU 대기 시간이 줄어든다.
```

---

## 8.5 write-through와 write-back을 비교하시오.

답안 구조:

```text
write-through는 캐시에 데이터를 쓸 때 주기억장치도 즉시 갱신하는 방식이다.
일관성이 좋지만 쓰기마다 주기억장치 접근이 필요해 성능이 저하될 수 있다.
write-back은 캐시에만 먼저 기록하고 해당 블록이 교체될 때 주기억장치에 반영한다.
쓰기 횟수를 줄여 성능이 좋지만 데이터 일관성 관리가 복잡하다.
```

---

## 8.6 Programmed I/O, Interrupt-driven I/O, DMA를 비교하시오.

답안 구조:

```text
Programmed I/O는 CPU가 장치 상태를 반복 확인하며 직접 전송하는 방식이라 단순하지만 CPU 낭비가 크다.
Interrupt-driven I/O는 장치가 준비되면 인터럽트로 CPU에 알려 CPU가 다른 작업을 할 수 있게 한다.
DMA는 CPU 대신 DMA 제어기가 메모리와 입출력장치 사이의 블록 전송을 수행하므로 대량 데이터 전송에 효율적이다.
세 방식은 CPU 관여 정도가 Programmed I/O > Interrupt I/O > DMA 순으로 감소한다.
```

---

## 8.7 인터럽트 처리 과정을 설명하시오.

답안 구조:

```text
CPU는 현재 명령어 실행을 완료한 뒤 인터럽트 요청을 확인한다.
인터럽트가 허용되면 현재 PC와 PSW 등 상태 정보를 저장한다.
이후 인터럽트 벡터를 이용해 ISR의 시작 주소를 찾아 PC에 적재하고 ISR을 실행한다.
처리가 끝나면 저장된 상태를 복구하고 원래 프로그램으로 복귀한다.
```

# Part 10. 최종 체크리스트

## 개념 설명 체크

- [ ] 제어장치의 구성 요소를 말할 수 있다.
- [ ] 고정 배선식과 마이크로프로그램 방식을 비교할 수 있다.
- [ ] 마이크로프로그램, 마이크로명령어, 마이크로연산을 구분할 수 있다.
- [ ] fetch cycle의 레지스터 전송 과정을 쓸 수 있다.
- [ ] instruction cycle의 전체 흐름을 설명할 수 있다.
- [ ] SRAM과 DRAM의 차이를 설명할 수 있다.
- [ ] ROM, PROM, EPROM, EEPROM, Flash를 구분할 수 있다.
- [ ] 캐시의 hit/miss와 지역성을 설명할 수 있다.
- [ ] 직접 매핑, 연관 매핑, 세트 연관 매핑을 비교할 수 있다.
- [ ] write-through와 write-back을 비교할 수 있다.
- [ ] 가상기억장치의 목적과 page fault를 설명할 수 있다.
- [ ] 디스크 접근 시간을 구성 요소로 나누어 설명할 수 있다.
- [ ] RAID 0, 1, 5의 차이를 말할 수 있다.
- [ ] 데이터 버스, 주소 버스, 제어 버스를 구분할 수 있다.
- [ ] Programmed I/O, Interrupt I/O, DMA를 CPU 관여 정도로 비교할 수 있다.
- [ ] 인터럽트 처리 순서를 말할 수 있다.

## 계산 문제 체크

- [ ] 주소선 수로 주소 개수를 구할 수 있다.
- [ ] byte-addressable과 word-addressable을 구분할 수 있다.
- [ ] 기억장치 칩 하나의 용량을 bit/byte 단위로 계산할 수 있다.
- [ ] 목표 기억용량에 필요한 칩 개수를 계산할 수 있다.
- [ ] 버스 폭과 클럭으로 대역폭을 계산할 수 있다.
- [ ] 디스크 용량을 표면·트랙·섹터·byte 수로 계산할 수 있다.
- [ ] 디스크 접근 시간을 탐색 시간, 회전 지연, 전송 시간으로 계산할 수 있다.
- [ ] AMAT를 hit time, miss rate, miss penalty로 계산할 수 있다.

# 마지막 10분 압축 복습

```text
제어장치: 명령어 해독 → 제어 신호 발생
고정 배선식: 빠름, 수정 어려움
마이크로프로그램: 유연, 상대적으로 느림
Fetch: PC → MAR → Memory → MBR → IR
기억계층: 빠를수록 작고 비싸다
SRAM: 빠름, 캐시 / DRAM: refresh, 주기억
캐시: 지역성 때문에 효과 있음
직접 매핑: 자리 고정 / 연관 매핑: 아무 자리
Write-through: 즉시 반영 / Write-back: 나중 반영
가상기억장치: 큰 메모리처럼 보이게 함
디스크 접근 시간: 탐색 + 회전 지연 + 전송
버스: 데이터 + 주소 + 제어
Programmed I/O: CPU가 직접 확인
Interrupt I/O: 장치가 CPU에게 알림
DMA: CPU 대신 블록 전송
인터럽트: 상태 저장 → ISR → 상태 복구
주소선 n개: 2^n개 주소
```
